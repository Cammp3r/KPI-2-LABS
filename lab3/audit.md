# Аудит — Завдання 3: Sequence-діаграми

## 1. Перевірка учасників

| Учасник діаграми | Відповідність моделі |
|---|---|
| User | відповідає сутності `USER` |
| SubmissionService | працює із сутністю `Submission` |
| Database | містить `Submission`, `Language`, `TestCase` та інші сутності |
| Judge | використовує тест-кейси для перевірки рішення |
| CodeRunner | внутрішній компонент системи для виконання коду |
| ResourceMonitor | внутрішній компонент для вимірювання runtime і memory |
| SubmissionController, Web UI | внутрішні компоненти системи |

Учасники `User`, `Submission`, `Language` і `TestCase` узгоджені з ER-моделлю. `Judge`, `CodeRunner`, `ResourceMonitor`, `SubmissionController` і `SubmissionService` є внутрішніми сервісами, тому в ER-моделі як сутності не представлені.

## 2. Перевірка кроків сценаріїв

Кроки `SC-07` і `SC-08` зі `spec.md` відображені на відповідних sequence-діаграмах:

- створення `Submission` зі статусом `Pending`;
- перевірка рішення на тест-кейсах через `loop`;
- отримання статусу `Accepted` у `SC-07`;
- зупинка перевірки та отримання статусу `Time Limit Exceeded` у `SC-08`;
- передача результату через Controller і Web UI користувачу.

## 3. Висновок

Sequence-діаграми відповідають основним крокам сценаріїв, містять реалістичні повідомлення, return-повідомлення, фрагменти `loop` і `alt`, а також activation bar для `Judge`, який починається до умовного фрагмента та завершується після нього.
